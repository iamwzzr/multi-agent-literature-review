## 修复行为

- Reporter 提出补证后，由 Reviewer 按程序分配的 request_id 判断是否为回答原问题所必需，并说明理由。只有明确覆盖原问题、逐项判为可选且其他审核门禁通过，才能免除补查。漏评、必要补证或未覆盖原问题仍阻止正式交付。
- 审核批次附带有界的全文提纲以判断问题覆盖；提纲不是原文证据。各批次仍须回读所审主张的原文，且所有主张均须审核。
- 一行比较请求遇到多行输出时，只有全部行满足原schema，才无损合并单元格、条件和引用ID，再审核。不会删掉不利事实来满足行数。
- 展示主张与审核主张使用相同的适用范围前缀；限定范围不能豁免事实矛盾。模型所写 limitations 仍按事实主张审核。
- Researcher 返回未知片段ID时，只允许一次基于真实候选原文的模型纠错，最多12个候选，消耗原有预算。程序不自动猜测或映射引用；再次未知、修复失败或执行错误均拒绝登记。原始错误与修复结果保留审计。
- 指标检查先移除引用ID，防止把 `evidence-f15…` 误识别为 F1 数值；实际出现的 F1/EM/ROUGE 得分仍由原检查拦截。
- 限制说明只保留其自己明确写出的引用，不再自动附上全部证据。未引用的限制说明产生可定位的引用缺陷，即使 Reviewer 误判通过，交付门禁也拒绝。
- Reviewer 评论中的未知引用、补证评估中的未知请求ID均保留审计并阻止通过；不渲染成真实引用，也不因状态处理崩溃而丢掉审计。
